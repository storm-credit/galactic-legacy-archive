## 1. 왜 필요한가

2026-08-08 위키링크 전환으로 **문서↔문서** 연결은 살아났지만, **개체(인물·기체·아이템·장소)** 연결은 여전히 없었다. 예를 들어 네라 비크의 정보는 다음처럼 흩어져 있고, 옵시디언에는 「네라 비크」라는 노트가 없어 백링크로 등장 지점을 모을 수 없었다.

- 말투 → [[core-canonical-names-and-voice-lock-v1]] §H-002
- 배경·사상 → [[hero-h002-mechanic-bible-v1]]
- 발음·충돌 → [[reader-facing-terminology-phonetics-and-register-bible-v1]]
- 액트별 역할 → 구간 캐스트 문서들
- 사망 회차 → 원고

엔티티 노트는 이 조각들을 **모으는 허브**다.

## 2. 절대 규칙

1. **엔티티 노트는 정본이 아니다.** 설정을 여기에 쓰지 않는다. 정본은 링크가 보유한다 (`CLAUDE.md` §3 복제 금지).
2. 요약은 **인물/개체를 알아보기에 충분한 최소한**까지만. 3~6문장.
3. 정본 출처 링크를 **최소 1개** 갖는다.
4. 노트 길이 상한 **60줄**. 넘으면 정본으로 옮긴다.
5. **`독자 노출 상한` 절을 반드시 갖는다.** 허브가 스포일러 창구가 되면 정보 상한(`CLAUDE.md` §8, 낭독 §6)이 무너진다.
6. **원고 본문에 위키링크를 넣지 않는다.** 출판 텍스트가 오염된다. 링크는 장면 카드·설계 문서·원고 **헤더**에만 쓴다.
7. 정본이 바뀌면 허브 요약도 같은 PR에서 갱신한다 (`CLAUDE.md` §12 전파 규칙).

C6 검사(`tools/validate_canon.py`)가 2·3·4·5를 기계로 강제한다.

## 3. 배치

```text
docs/_entities/
  characters/   인물
  frames/       기체
  items/        유물·권한·장치
  places/       장소·기관
```

파일명은 정본 한글 상용명을 쓰고 공백은 `-`로 바꾼다. 저장소 전체에서 파일명이 유일해야 한다 (C1이 중복을 ERROR로 잡는다).

## 5. 채택 근거

시안 비교와 맹점 훑기는 [[entity-layer-design-options-and-blindspot-sweep-2026-08-08]]에 있다. 요약하면 **시안 A(링크 허브)를 기반으로, 시안 B의 속성은 정본에 없는 메타데이터로만 제한하고, 시안 D의 액트별 추적은 별도 노트가 아니라 허브 안의 절로 흡수**했다. 시안 C(태그 색인)는 기각했다 — 태그는 노트가 아니라 그래프에 연결선을 만들지 못한다.
