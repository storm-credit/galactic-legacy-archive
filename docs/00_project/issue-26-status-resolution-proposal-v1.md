## 1. 모순의 정확한 구조

issue #26(인간/모바일 독자 테스트)의 지위에 대해 세 문서가 서로 다른 답을 준다:

| 문서 | 판정 | 근거 위치 |
|---|---|---|
| A. `prewriting-gate-dry-audit-2026-08-03.md` + `prewriting-gate-evidence-matrix-v2.md` | **집필 전 하드 블로커** (B1~B7). §7은 "#26을 선택사항으로 선언하는 것"을 명시적으로 금지 | dry-audit §5, §7; matrix §12 |
| B. `autonomous-completion-validation-override-2026-08-03.md` | **출판 전 블로커로 재분류** — AI 프록시 8세션을 "내부 초고용으로만" 인정, 인간 검증 주장 금지, 인간 결과가 나오면 E1~5 재수정 강제 가능 | override §4 |
| C. `design-only-scope-restoration-2026-08-03.md` | 중립 — "#26은 설계 작업의 전제조건이 아니며, 미래의 명시 승인된 집필 단계를 위해 열려 있다" | restoration §4 |

**모순의 핵심은 A vs B가 아니라, C가 B를 무효화했는지다.** restoration §2는 "그 프로즈를 정당화하는 것이 유일 목적인 승인/상태/감사 문서"를 비정본으로 판정했고 §8은 PR #34~36의 프로즈 승인을 supersede했다. override는 바로 그 프로즈 승인을 가능하게 한 문서이므로:

- **해석 1**: override 전체가 무효 → #26은 A(집필 전 블로커)로 복원됨.
- **해석 2**: override 중 "프로즈 승인" 부분만 무효, "#26 재분류" 부분은 위험관리 프레임으로 존속 → #26은 B(출판 전 블로커).

두 해석 모두 문서상 성립 가능하며, 이것이 readiness audit F-02(S1)의 실체다. 어느 해석을 따르느냐에 따라 첫 배치 착수 가능 여부가 갈리므로 기계적 해소가 불가능하고 작가 판정이 필요하다.

## 2. 제안 판정

> **issue #26을 "출판 전(pre-publication) 하드 블로커"로 확정한다.**
> **단, 과거 override 문서를 복권하는 방식이 아니라, 게이트 개방 선언에 딸린 신규 작가 판정으로 확정한다.**

즉 해석 1을 수용하되(override는 비정본 유지 — 정본 계층을 건드리지 않음), 같은 내용의 재분류를 **작가의 새 결정**으로 다시 내리는 방식이다. 이러면 "비정본 문서가 정본 규칙을 만들었다"는 오염 경로 없이 모순이 소거된다.

## 3. 제안 근거

1. **테스트의 목적물이 원고다.** #26이 검증하려는 것(모바일 가독성·문단 리듬·음성 구별·열독 지속 의사)은 산문 전달력이다. 집필 전에 실행하면 검증 대상이 비정본 샘플뿐인데, 그 형태의 검증은 이미 AI 프록시로 소진했다. 개정된 실제 E1~2를 시료로 쓰는 편이 테스트 가치가 높다.
2. **dry-audit 자신의 논리와 호환된다.** dry-audit §8의 경고는 "연재를 시작한 뒤 첫 20화를 다시 쓰는 비용"이다. 이 위험은 **출판**에서 발생하지, 수정 유연성이 보존된 초고 단계에서는 발생하지 않는다. `Publication: NOT AUTHORIZED`가 유지되는 한 §8이 보호하려는 가치는 그대로 보호된다.
3. **일정.** 2026년 9월 공모전까지 약 1개월. 인간 테스트를 집필 선행 조건으로 두면 모집·실시·결과정리 기간이 집필 가능 기간을 잠식한다. 병행하면 개정 초고 완성과 테스트 결과가 같은 창구에 수렴한다.
4. **과거 사고의 원인과 다르다.** 08-03 스코프 사고의 문제는 "작가 지시 없는 자동 프로즈 생산"이었지 재분류 논리 자체가 아니었다. 이번에는 게이트 개방 자체가 작가의 명시 선언으로만 발효되므로 같은 사고 경로가 없다.

## 4. 위험 통제 (판정에 딸린 조건 — 전부 유지 의무)

1. **출판·공개·유료연재는 인간 테스트 결과 기록 및 기준 통과 전까지 차단** — 모든 원고 파일의 `Publication: NOT AUTHORIZED` 헤더 유지.
2. **첫 배치와 병행하여 인간 테스트 실행**: `docs/99_quality_control/gate8-human-mobile-test-packet-v1.md` 절차 그대로 — 최소 5인, 절반 이상 휴대폰 화면, 시료는 개정 E1~E2 + white-dock 샘플.
3. **인간 결과가 수정을 요구하면 E1~20 개정은 수용 비용으로 확정** — 초고는 미출판 상태이므로 재작업 가능성을 전제로 진행.
4. **결과 기록 전까지 어디에도 "인간 검증 완료"를 주장하지 않는다** (AI 프록시 결과를 인간 결과로 표기 금지).
5. GitHub issue #26은 결과 기록 시까지 OPEN 유지.
6. 반복 실패 패턴(동일 항목 2회 이상 임계 미달)이 나오면 집필 중단 후 문체 캘리브레이션 재실행.
