## 1. Audit Result

기존 18개 역할은 프로젝트 범위를 넓게 덮지만, 깊은 설계와 검증을 위해서는 **부서장 역할**로만 사용해야 한다. 실제 작업은 `specialist-roster.md`의 세부 전문가가 수행한다.

핵심 발견:

1. 군사·함대·전술을 한 명이 맡을 수 없다.
2. 기체·함선·무장도 공학·생산·전술·시각설계를 분리해야 한다.
3. 수집형 재미는 도감만으로 완성되지 않으며 게임루프·희귀도·조합·보상·손실·인플레이션 전문가가 필요하다.
4. 적대·제3세력은 주인공 세력과 같은 품질의 별도 전문가 검증이 필요하다.
5. 회귀는 설정 한 줄이 아니라 시간인과·나비효과·미래정보 신뢰도를 관리하는 독립 분야다.
6. 작문법은 문체와 맞춤법만이 아니라 장면공학·시점·감정·정보·긴장·전환·회차구조로 분리해야 한다.
7. 전문가 수를 늘리는 것만으로는 부족하며, 자동 호출 조건과 권한 경계를 명확히 해야 한다.

## 5. Conflict Resolution

전문가 충돌 예:
- 과학적으로 맞지만 전투가 재미없음
- 게임적으로 보상감이 있지만 인물 존엄을 해침
- 군사적으로 효율적이지만 정치적으로 불가능
- 문체가 빠르지만 감정 회수가 부족

처리 순서:
1. 충돌하는 목표를 명시
2. 반드시 지켜야 할 정본 제약 확인
3. 대안 3개 이상 제시
4. 독자 재미·인과·주제·장기 파급 비교
5. O00 결정
6. O03 변경 영향 기록

## 6. Too-Many-Agents Safeguard

- 한 문서의 직접 작성자는 한 명이다.
- 교차검토는 기본 2~5명으로 제한한다.
- 동일 지적은 O00이 통합한다.
- 전문가는 자기 분야 밖 문장을 직접 수정하지 않고 문제와 요구조건을 전달한다.
- 모든 의견을 반영하지 않는다. 충돌하는 요구를 선택하고 이유를 기록한다.

## 7. Final Audit Verdict

현재 필요한 전문 영역은 `specialist-roster.md`로 충분히 덮었다. 이후 새 에이전트를 추가할 조건은 다음뿐이다.

- 기존 전문가가 검증할 수 없는 새로운 학문·장르가 핵심 플롯에 등장
- 반복적으로 같은 누락이 발생
- 기존 역할을 넓히면 검증 품질이 명백히 떨어짐

현재 즉시 추가가 필요한 별도 핵심 분야는 없다. 다만 실제 참고작·게임 분석과 세계관 설계 과정에서 필요성이 증명되면 의료, 생명공학, 첩보극, 추리, 로맨스, 공포, 코미디 전문가를 Specialist Bench에서 승격한다.
