## 1. Purpose

The Collection Bible already locks four reader drives:

1. Discovery — 무엇인지 알고 싶다.
2. Acquisition/Connection — 비용을 치르고 관계·접근·운용·권리를 확보하고 싶다.
3. Synergy — 사람·기체·함선·기술·제도를 실제 임무에서 조합해 보고 싶다.
4. Completion/Legacy — 흩어진 계보·사건·문명의 의미가 어디에 남는지 확인하고 싶다.

The remaining execution problem is not inventing more collectibles. It is making those four drives visible at every approved subact so the long series does not turn into disconnected registry administration.

This standard therefore binds existing collection rows to existing subacts without changing story events.

## 2. Non-Negotiable Boundary

This layer may:

- group existing registry rows into author-side reader-desire threads;
- map existing targets to the subacts where their approved episode windows are active;
- classify a subact under the five Collection Bible set families;
- foreground an already-approved relationship, object, right, place, service or legacy state;
- state the existing reward, cost, refusal, loss and next desire more explicitly for drafting.

It may not:

- create a new person, mecha, ship, weapon, relic, technology, faction, node or civilization;
- create a new death, injury, relationship, authority or ownership right;
- revive an irreversible loss to complete a set;
- change an approved episode range, act result, payoff timing or ending;
- convert a human/person/community into inventory ownership;
- convert access into title, custody into command, discovery into territorial ownership or a blueprint into industrial capability;
- promote any proposed relic simply to satisfy a per-GA quota;
- change the reader-facing name of C1 without a separate author decision;
- use manuscript prose as a source of story facts.

If an execution mapping would require any forbidden addition, record `NEW_CANON_REQUIRED: YES-STOP` and do not complete that mapping.

## 3. Stable Execution IDs

### `CLT-*` — Collection Thread ID

One stable author-side ID per existing registry source row.

Purpose:
- preserve the 415-row source registry without pretending every row is a unique physical collectible;
- connect state/relationship/claim/loss/promise rows to reader-desire execution.

Important:
- two `CLT-*` IDs may still refer to different states, claims or promises around one underlying subject;
- `CLT-*` is not a unique-entity census claim.

### `CLSET-*` — Subact Set Execution ID

One author-side set/reward execution ID per approved subact.

Purpose:
- make the current discovery → connection/acquisition → use/synergy → legacy advance visible;
- connect the reward to a cost and next desire.

Important:
- it is not an in-world Archive set;
- it creates no new object, right or historical fact.

## 4. Canonical Set Families

Only the five already defined by the Collection Bible may be used:

1. `LINEAGE` — 계보 세트.
2. `EVENT` — 사건 세트.
3. `FUNCTIONAL` — 역할 조합 세트.
4. `RELATIONSHIP` — 관계 세트.
5. `CIVILIZATION` — 문명 복원 세트.

A subact may have one primary type and several secondary types. Completion may mean reinterpreting, returning, dispersing, institutionalizing or permanently losing something; it does not imply collecting everything into Rian's possession.

## 5. Required Subact Fields

Every approved subact must have:

- `SET_EXECUTION_ID`
- `PRIMARY_SET_TYPE`
- `SECONDARY_SET_TYPES`
- `FRONT_DOMAINS`
- `READER_DESIRE_MAIN`
- `DISCOVERY`
- `ACQUISITION_OR_CONNECTION`
- `SYNERGY_OR_USE`
- `COST_REFUSAL_OR_LOSS`
- `SET_ADVANCE_CONDITION`
- `NEXT_DESIRE`
- `OWNERSHIP_GUARD`
- `ACTIVE_TARGETS` — normally 1–5 source-bound `CLT-*` threads
- `SOURCE_SUBACT`
- `NEW_CANON_REQUIRED`

The target is not to expose every registry row to the reader. The target is to keep only a small active set while preserving long-term background and legacy rows.

## 6. Match Depth

`A-DIRECT`
- at least one active thread has an explicit approved episode overlap with the subact.

`B-TEXTUAL`
- no explicit episode overlap was captured, but the act/subact text directly names or clearly matches the source target.

`B-FALLBACK`
- only nearest explicit source-window routing was possible.

Final integration condition:
- all B rows must be manually inspected and either upgraded through source-bound evidence or explicitly accepted as a documented non-front-stage exception.
- zero-target subacts are not allowed.

## 7. Reader-Memory and Reward Rules

- active front-stage targets: normally 3–5 or fewer;
- the same person, ship, place, claim or service should re-enter after state change rather than be replaced by a new noun;
- a reward must be used, tested, refused, lost or politically reinterpreted after acquisition;
- acquisition methods rotate across rescue, negotiation, court/claims, repair, certification, salvage, trade, exploration, combat, public disclosure and institutional agreement;
- every apparent completion must leave either responsibility, cost, autonomy, loss, upkeep or a changed next question;
- later GA rewards must not erase the usefulness or memory of earlier people/equipment/institutions.

## 8. Domain Guards

### C1 — people/relationships

- desire is contact, understanding, trust, agreement, rivalry, cooperation, departure or succession;
- never loyalty-as-loot.

### C2/C3/C5/C6 — frames/tools/ships/technology

- physical possession is separate from certification, maintenance, crew, ammunition, tooling, industry, legal use and doctrine.

### C7 — factions/institutions

- recognition or compact is separate from owning the institution;
- constituency, internal factions, appeal and succession survive protagonist absence.

### C8 — territory/nodes/civilizations

- discovery/access/service/defense/jurisdiction/meaning are separate;
- residents and prior claims cannot disappear because a node was 'acquired'.

## 9. Semantic-Merge Resolution

The older normalization work intentionally held on a unique-entity count because the 415 rows contain mixed entities, relationships, claims, state transitions, losses and promises.

This execution layer resolves that blocker for story production by using stable **source-thread IDs** rather than inventing unsupported unique-entity identities.

Therefore:

- `unique physical entity count` is not required for reader-desire completion;
- all 415 rows must nevertheless receive a stable thread ID and set-family/desire-phase routing;
- actual alias/entity deduplication remains an encyclopedia/catalogue maintenance task and may not silently change canon.

This is a deliberate normalization decision, not an unresolved omission.

## 10. Completion Gate

The full-series collection-desire layer is complete only when:

1. 415/415 source rows have stable `CLT-*` execution threads;
2. all GA1–GA10 approved subacts have `CLSET-*` maps;
3. zero subacts have zero active targets;
4. mandatory reader-desire fields are all present;
5. B-depth queue is manually closed;
6. repeated set/target patterns have been Red-Teamed for spreadsheet feeling and protagonist ownership creep;
7. named irreversible losses and GA10 ending are not contradicted;
8. `NEW_CANON_REQUIRED: YES-STOP` count is 0;
9. canon/link validation passes apart from already-recorded unrelated generated-index debt.
