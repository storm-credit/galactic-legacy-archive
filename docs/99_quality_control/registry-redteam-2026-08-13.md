## 1. 왜 이 문서가 있는가

2026-08-13에 등록부 6종(함선·무기·기술·유물·세력·장소)과 하중 필드 237건을 만들고, 같은 날 그것을 근거로 집필 게이트를 `CONDITIONAL PASS`로 채점했다.

작가가 물었다 — **"정말 오케스트라가 판단해서 다 된 거야?"** 확인 결과 두 가지가 사실이 아니었고, 확인 과정에서 셋째가 나왔다.

**원인은 산수가 아니라 절차다.** 이미 권위가 있는데 참조하지 않고 병렬 규칙을 세웠다. §3(단일 정본 문서와 링크) 위반이기도 하다.

## 3. 채택 수정

### F1 — 등록부의 노출 상한을 폐기하고 권위로 라우팅

각 등록부 §5는 자기 숫자를 갖지 않는다. **[[reader-facing-terminology-phonetics-and-register-bible-v1]] §2 예산을 인용**하고, 도메인 고유의 내용(무엇이 전면이고 무엇이 배경인가)만 유지한다.

전면/배경 구분은 **어느 항목이 예산 안으로 들어올 자격이 있는가**의 목록이지, 몇 개를 부를 수 있는가의 허가가 아니다.

### F2 — 첫 등장 시 종류어 동반 의무

어근으로 종류를 구별할 수 없으므로 **문장이 구별한다.** 고유명의 첫 등장에는 종류어를 붙인다 — `전열함 유덱스`, `카빈 사기타`, `헬릭스 규격 노르마`, `봉인 열쇠 클라비쿨라`. 재등장부터는 생략 가능하다.

이것은 실제 산문이 원래 하는 일이며, 어근을 다시 배분하는 것보다 싸고 정확하다.

### F3 — 원고 검토를 정본 예산으로 교체

`tools/revision_checklist.py`가 도메인별 상한 대신 **회차당 최초 사용 고유명 0–4**를 센다. 정본이 세는 방식으로 센다.

### F4 — 게이트 재채점

D3 해당 5건을 `PASS` → `PASS (자기 인증)`으로 표시하고, 전체 판정을 `CONDITIONAL PASS` → **`HOLD`**로 되돌린다. 오늘 만든 문서가 독립 검토를 받기 전까지 게이트는 열리지 않는다.

## 4. 이 검토의 한계 — 오케스트라가 아니다

`CLAUDE.md` §15-1: *"실제 Codex 하위 에이전트를 실행한 경우에만 에이전트 ID와 결과를 실행 증거로 남긴다. 역할명 헤더만으로 독립 실행을 주장하지 않는다."*

오늘 만든 등록부 6종은 `Owner Agents: A00 Novel PM / H03 Weapons-Sensors-EW / ...` 헤더를 달고 있으나 **에이전트 ID가 없다.** 단일 에이전트가 쓰고 역할명을 붙인 것이다. 기존 문서 일부는 실제 ID(`019fef77-…`)를 갖고 있으므로 대비된다.

이 문서도 마찬가지다. **등록부를 만든 주체가 자기 것을 검토했다.** D1·D2는 계산으로 확정되므로 주체와 무관하지만, **놓친 것이 더 있는지는 이 검토로 알 수 없다.**

독립 검토가 필요한 항목:

1. 하중 필드 237건의 회수 시점이 액트맵·회수 장부와 정합하는가
2. W10 도구 4종으로 20화 분량의 전투가 성립하는가
3. 등록부 6종의 내용이 기존 정본과 모순되지 않는가 (기계 검사는 링크·계수·대액트만 본다)
