## 2. Weapon Reader-Memory Rule

A weapon earns a reader-facing name only if at least four are true:

1. reused across more than one meaningful scene/window;
2. has a host/fit problem;
3. has a distinctive handling/stowage/heat/ammo cost;
4. creates a nontrivial tactical option, not only higher damage;
5. is lost/repaired/transferred/inherited;
6. reveals manufacturer/faction/service history;
7. a character/crew changes doctrine because of it;
8. readers would notice its absence.

If not, use functional wording rather than a proper noun.

## 3. Opening 07 Tool Identity

Existing canon opening tools should remain the strongest early C3 anchors:

- thermal cutting lance;
- cable launcher;
- low-velocity training projector;
- shield plate.

They are deliberately not `legendary weapons`.

Their desire engine is combination:
- cut/open;
- anchor/tow;
- mark/disable/train;
- protect/brace.

Reader promise:
> 07 wins by using mundane tools in combinations that preserve people, data and infrastructure.

Hard veto:
- renaming all four into flashy artifact weapons;
- adding hidden ultimate mode;
- replacing them immediately with higher-output guns;
- treating rescue/capture tools as starter trash.

## 4. Later Weapon Portfolio — Promotion Filter

The 40 proposed named anchors should be treated as a **candidate pool**, not a required reader catalog.

Before canon promotion each candidate must answer:

- What existing episode/operation needs it?
- Why an existing W-family generic item cannot do the same job?
- What host accepts it?
- What cooling/ammo/energy/certification cost appears on-page?
- What visual/handling feature makes it memorable?
- Does it survive long enough to justify a proper noun?
- What old tool remains useful after this appears?

Recommendation:
- approximately 1–2 signature reusable tools/weapons per Grand Act may be reader-named if demand proves it.
- this is a planning target, not a canon quota.
- GA9 should continue no-new-chassis logic and should be conservative about new weapon names too.

## 5. Tactile Anchor Template — Weapons

For a FRONT weapon/tool:

1. stowed shape;
2. draw/deploy path;
3. one handling sound;
4. heat/recoil/drag behavior;
5. ammunition/energy state readers can understand;
6. maintenance point;
7. failure state;
8. noncombat use;
9. countermeasure;
10. visible scar/wear state after major use.

Do not require exact engineering numbers in prose unless scene-critical.

## 6. Relic Problem — Current Reality

The proposed relic registry is strong as an ideation taxonomy:

- provenance/navigation;
- symbolic/legitimacy;
- cultural/ritual;
- memory/scar;
- fragment/forgery.

But none of the 28 physical entries is currently canon.

Therefore:

- do not count `28 relics` as completed collection content;
- do not insert them into scene cards to satisfy a collection quota;
- do not name them in manuscript Context Packs as existing facts;
- use existing story evidence objects first.

## 7. Existing-Object-First Rule

Before proposing a new C4 physical relic, inspect whether the story function is already served by:

- service key;
- original log/media;
- registry/seal;
- authenticated fragment;
- custody record;
- ship/frame part with provenance;
- memorial/name plate;
- physical archive medium;
- original/forged document;
- returned community object already implied by canon.

If one exists, deepen its physical identity instead of adding a new relic.

## 8. What Makes An Evidence Object Collectible

Not rarity alone.

A good evidence-object desire loop:

1. rumor — reader knows something physical exists;
2. trace — sees damage/partial copy/forgery;
3. custody race — several actors want different outcomes;
4. authentication — object does not automatically prove interpretation;
5. cost — carrying/opening/disclosing it changes politics or safety;
6. return choice — rightful community/holder may want it back;
7. reinterpretation — later record changes what reader thought the object meant;
8. legacy — original may leave protagonist custody.

## 9. Visual/Tactile Rules For Relics

If/when a physical relic is approved:

- no generic glowing alien cube;
- age must show manufacturing/storage history, not fantasy magic patina;
- authentication marks must be physically/forensically meaningful;
- object scale must fit its actual use;
- damage/repair should affect interpretation;
- replicas/forgeries may look cleaner than originals;
- community object must have ordinary use history, not exist solely for protagonist discovery.

## 10. Blind Spots

### W-R1 Name inflation

44 names become noise if most appear once.

### W-R2 Visual escalation

larger gun = stronger desire is forbidden; tool combination and fit are the project’s differentiator.

### W-R3 Relic quota

forcing one physical relic per GA would invent lore after architecture is already complete.

### W-R4 Provenance without touch

records can become abstract unless some crucial evidence has scale, damage, custody and handling constraints.

### W-R5 Museum ending

collection completion cannot end with Rian owning a room of artifacts.
