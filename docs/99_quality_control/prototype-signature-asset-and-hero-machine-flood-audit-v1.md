## 0. Risk

A numbered prototype program creates an obvious but harmful temptation:

> important character = important prototype machine.

If repeated, this would:
- turn the ensemble into a roster of collectible pilots;
- make nonpilot expertise secondary;
- imply every important historical machine survives into current hero hands;
- shrink fleet/route/institutional scale back into duels;
- make the 01–20 program a treasure checklist.

Existing collection/role-demand design already rejects this structure.

# 2. Rivals, admirals and political actors

## Ace/rival class

Some recurring antagonists/rivals may deserve:
- custom hull;
- limited-run modern chassis;
- institutional heirloom;
- heavily rebuilt mass frame.

But only a minority should be historical prototype survivors.

Default priority:
1. current mass/custom ecosystem;
2. modern special-production machine;
3. prototype-descended design;
4. surviving historical P-slot only if plot cannot work otherwise.

## Admirals/fleet commanders

Signature identity should usually be:
- flagship;
- formation doctrine;
- command arrangement;
- fleet constituency;
- withdrawal/refusal rules.

Do not make every admiral secretly an ace with a relic frame.

## Claimants/houses/orders

Possible assets:
- household guard formation;
- legal seal;
- yard contract;
- standard frame family;
- heirloom hull.

Ancient prototype possession should be rare and create legal/logistical consequences, not prestige decoration.

## Aurel / Continuity

Signature asset is:
- office/process/service architecture;
- reconciliation/coordination network;
- current human/AI institutional embodiment.

Do not reduce Aurel to a final super-frame or prototype core.

# 3. Recommended present-day origin mix for memorable machines

This is a planning balance, not a count lock.

Reader-facing notable machines should come from several origin classes:

1. **historical prototype survivor/rebuild** — rare;
2. **prototype-descended modern special**;
3. **mass-production ace custom**;
4. **institutional/house/order heirloom**;
5. **frontier rebuild / donor composite**;
6. **modern experimental article**;
7. **rescue/service specialist**;
8. **ordinary mass chassis with exceptional hull history**.

No single class should own all important pilots.

---

# 4. Historical P-slot survival ceiling principle

The prototype program can contain many historically important slots without many current surviving whole machines.

Preferred present-day pattern:
- several P-slots: record only;
- several: components/fragments;
- several: descendant technologies only;
- few: sealed/institution-held article or partial hull;
- very few: operational current whole/rebuilt frame.

This is why provenance axis must remain separate from developmental success.

An O3 lineage-success can be R0/R1/R2 today.
An O1 failed frame can leave one famous fragment or accident site.

---

# 5. Character assignment gate

Before assigning any P-slot or direct P-slot descendant to a named recurring character, prove all seven:

1. **Role need** — the character’s existing story requires this asset class.
2. **No compensation design** — it is not being added because another character has a cool machine.
3. **Current-world support** — parts, cradle, cooling, certification and operator support exist or their absence is story cost.
4. **Independent history** — the machine existed for reasons unrelated to meeting this character.
5. **Loss path** — damage/loss/retirement can occur without breaking the character’s entire narrative function.
6. **No authority inflation** — owning/piloting it grants no unrelated legal/political command.
7. **Reader return** — the machine has more to say than “rare number from the old set.”

Fail one:
- use a modern/shared/rebuilt asset instead.

# 6. Prototype-program allocation implication

When P-01…P-20 outcomes are eventually drafted:

Do not reserve numbers for:
- one per core ally;
- one per claimant;
- one per major faction;
- one per GA;
- one per ace rival.

Instead allocate by historical engineering problem and institutional consequence.

Only **after** a slot’s independent history exists may a present character intersect it.

This preserves causal direction:

> history creates assets → current people encounter/contest/use them

not:

> cast needs cool assets → history is invented backward to supply them.

# 8. Red-team tests

Reject a future allocation if:
- the number itself is the main reason it is cool;
- character relevance drops if the prototype label is removed;
- the machine solves the character’s nontechnical conflict;
- every important faction ends up with a prototype;
- old machines dominate modern supported performance;
- current mass-production doctrine becomes background filler;
- ordinary crews stop mattering;
- the prototype cannot be lost because it carries too much plot;
- one surviving set forms the final-party roster.
