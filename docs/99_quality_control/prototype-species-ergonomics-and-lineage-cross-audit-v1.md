## 1. Audit Question

Should the newly designed multi-species world cause the 01–20 prototype program to be reinterpreted as a “multi-species mecha project”?

Answer:

> **NO. Multi-species ergonomics should be one historical pressure among several, not the hidden purpose of the whole prototype program.**

The prototype architecture already has stronger root drivers:
- service interoperability;
- mobility;
- heat;
- damage tolerance;
- repair;
- cradle compatibility;
- rescue/capture;
- sensors/EW;
- command;
- bounded AI;
- authentication;
- low-logistics use;
- mass manufacture;
- modular conversion.

Species diversity should affect only the hypotheses where body/service/interface differences materially change engineering.

## 2. Hypothesis Classification

### P0 — Species-neutral at root

These questions remain fundamentally machine/fleet/industry problems:
- H01 multi-role structural family;
- H02 multi-environment mobility;
- H04 endurance versus surge;
- H05 modular thermal architecture;
- H06 damaged/manual fallback;
- H08 field repair;
- H10 rescue/capture under fire;
- H11 controlled breach;
- H12 sensor fusion;
- H13 localized EW;
- H14 formation command;
- H16 bounded AI responsibility;
- H18 weak-logistics operation;
- H19 mass manufacture;
- H20 modular mission conversion.

Species differences may appear in test crews or adapters, but do not redefine the hypothesis.

### P1 — Species-sensitive secondary pressure

#### H03 high-acceleration vector control

Species relevance:
- pilot restraint;
- circulation;
- organ support;
- different acceleration envelopes.

Control:
- do not invent a “Braxi high-G prototype.”
- chassis acceleration is constrained by structure, mission, cargo and mixed crews as well as pilot physiology.

#### H09 cradle commonality

Species relevance:
- cockpit/service capsule geometry can add dead mass or swap time.

Control:
- cradle compatibility should prioritize machine family and service interfaces; pilot module compatibility is a secondary layer.

#### H15 human-machine coupling

This hypothesis must be renamed conceptually before canon promotion if the historical era is already multi-species.

Safer wording:
> `operator-machine coupling` rather than `human-machine coupling`.

Possible tests:
- neural;
- muscular;
- tactile;
- non-neural translated control.

Control:
- one nervous-system standard cannot become universal.

#### H17 emergency authority

Species relevance:
- identity/personhood systems must not depend on one anatomy or biometric assumption.

But:
- the core problem is institutional authorization, not biology.

### P2 — Direct multi-species/service pressure

#### H07 mixed-contractor service / diagnostics / emergency interfaces

This is the strongest safe connection.

A mature version of H07 can include:
- body-neutral maintenance controls;
- interchangeable cockpit/service modules;
- diagnostic systems that distinguish machine state from operator biology;
- rescue interfaces with multiple service profiles.

Important:
- **07 itself does not need to fit every species.**
- 07's successful inheritance can be an *interface philosophy* that makes later adapter ecosystems easier.

This preserves existing 07 canon:
- service/interoperability first;
- not universal supermachine;
- later open-standard influence.

## 3. What Must Not Happen

### RT-01 — “All twenty prototypes were built for different alien species”

Reject.

Why:
- converts engineering history into a species collectible set;
- implies one prototype per species;
- makes modern machine ecology too neat.

### RT-02 — species-specific chassis inflation

Reject default:
- Braxi machine;
- Seia machine;
- Numar machine;
- Kelik machine;
- etc.

Use separate chassis only if:
1. standard cockpit/module adaptation repeatedly fails;
2. mission advantage is substantial;
3. user population or institution is large enough;
4. production/maintenance base exists;
5. the design has users beyond one named ace.

### RT-03 — 07 as universal cross-species neural machine

Reject.

07 may contribute:
- open service bus;
- physical adapter conventions;
- emergency authority grammar;
- rescue interface philosophy.

It does not automatically provide:
- universal neural compatibility;
- perfect translation;
- every atmosphere;
- every limb mapping;
- species-independent acceleration.

### RT-04 — aliens as explanation for old technology superiority

Reject.

Nonhuman institutions can contribute to standards and technology history, but old prototypes still carry:
- material limits;
- certification problems;
- maintenance cost;
- obsolete components;
- failed assumptions.

### RT-05 — AXIOM becomes alien master blueprint

Reject unless a later explicit canon change authorizes it.

Current safe boundary:
- AXIOM remains a separate legacy-machine mystery candidate;
- it is not the parent of all 01–20 prototypes;
- one piece of historical external technology could influence one experiment only after separate approval.

## 4. Recommended Historical Relationship

If IMP-D is eventually approved, the safest sequence is:

```text
independent human + nonhuman technological traditions
        ↓
centuries of contact / wars / standards pressure
        ↓
mixed Imperial / provincial / industrial technical ecosystem
        ↓
Foundational Demonstrator Program
        ↓
01–20 authorized experimental slots
        ↓
partial successes / failures / lineage successes
        ↓
modern production families + adapters + doctrines
```

This means:
- the prototype program is not “first contact tech”;
- cross-species service problems are already known by then;
- the program tries to solve broader military/industrial limitations in a diverse civilization.

Exact chronology remains HOLD.

## 5. Species-by-Species Machine Implications

### Braxi
First solution:
- cockpit restraint/limb control adapter.

Separate chassis need:
- low by default.

Possible dedicated machine justification:
- industrial/high-load work, not species pride.

### Seia
First solution:
- low-acceleration mission profile;
- distributed restraint;
- remote/low-g service controls.

Separate chassis need:
- mission-dependent, not biological inevitability.

### Numar
First solution:
- sealed fluid-support cockpit module.

Separate chassis need:
- higher than most if sustained fluid support changes mass/thermal/escape architecture, but only after support economics pass.

### Ivra
First solution:
- biomonitoring/medical compatibility.

Separate chassis need:
- very low; biology does not require different frame geometry.

### Tesar
First solution:
- multi-limb control translation and seat geometry.

Separate chassis need:
- low for combat; potentially higher for industrial machines designed around five-limb direct mapping.

### Kelik
First solution:
- EM filtering / alternative sensory display.

Separate chassis need:
- low; sensor interface is more important than chassis.

### Verin
First solution:
- individual physiological profile in cockpit/service system.

Separate chassis need:
- none by ancestry alone.

## 6. Prototype Slot Assignment Rule Update

When final numbers are eventually assigned, each slot packet must include:

- primary engineering hypothesis;
- secondary hypotheses;
- sponsor/institution;
- operator population assumption;
- whether multi-species operation was tested:
  - `N` not material;
  - `A` adapter-compatible only;
  - `M` multiple operator profiles actively tested;
- developmental result O0–O4;
- present provenance R0–R5;
- later primary lineage;
- later secondary inheritance;
- failure lesson;
- story reveal use.

Important:
- `M` should be uncommon enough to remain meaningful.
- a slot does not become more advanced simply because it tested multiple species.

## 7. 07 Working Classification

Current NONCANON recommendation:

- Primary hypothesis: H07 service/diagnostic interoperability.
- Secondary: H10 rescue/capture + H17 emergency authority.
- Multi-species test status: **A or M remains HOLD**.

Safer default before historical evidence:
- `A`: architecture is adapter-friendly, but there is no claim 07 itself completed full multi-species pilot certification.

This avoids retconning the existing cockpit/Academy state.

## 9. Audit Verdict

> **PASS — multi-species worldbuilding strengthens prototype/service history only when treated as a bounded interface and institutional pressure. It must not become the hidden master purpose of 01–20.**

No existing prototype outcome, number, date or 07 designation is canonized by this audit.
