## 1. 목적

이 문서는 실제 원고를 `narration-harness-v1.md`, `prose-bible.md`, `revision-harness.md`, 현행 인물 voice lock에 대조해 **소리 내 읽을 때 발생하는 문제만** 분리 기록한다.

사건, 설정, 사망 여부, 관계, 숫자, 결말, 복선의 의미를 변경하지 않는다. v1 초안에 남은 구명·구표기는 역사적 초안 보존 규칙에 따라 그 자체를 현행 정본 위반으로 판정하지 않는다. 다만 실제 낭독 대상 본문/UI에 구명이 노출되면 낭독 준비 결함으로 기록한다.

## 2. 판정 기준

- **PASS**: 현행 낭독 하네스를 적용하면 즉시 읽어도 구조적 장애가 없다.
- **PATCH**: 국소 문장, 호흡, 표기 또는 낭독 지시를 보정하면 해결된다.
- **REWORK**: 기계음/UI 반복, 기록문 연속, 리듬 파편화 등으로 문단·장면 단위 정리가 필요하다.

판정은 **낭독 준비도**만 뜻한다. AUTHOR-APPROVED, 정본 승격, 공개·출판 승인을 뜻하지 않는다.

## 3. 전역 낭독 잠금

1. 리안 시점은 차분한 감각·판단 중심의 근접 3인칭을 유지한다. 해설자가 미래 의미를 알려주는 듯한 억양을 금지한다.
2. 기본 호흡은 중간 길이 문장이다. 충격·선택이 아닌 곳에서 짧은 문장을 연속 타격음처럼 읽지 않는다.
3. `[ ... ]` 시스템/아카이브 출력은 감정 없는 기계음으로 읽되, 장면을 기계음이 지배하지 않게 한다.
4. 물리 표지·인쇄 문서는 시스템 음성으로 읽지 않는다.
5. 무전은 통제된 교신 톤, 전투는 속도만 올리고 문장을 토막 내지 않는다.
6. 기관 문서·심문·기록은 평문과 구별되는 공식 톤을 사용한다.
7. `07호`는 **공칠호**로 읽는다.
8. 숫자는 한국어 자연 발음으로 읽는다. 예: `11.6 m` → `십일 점 육 미터`.
9. 조기 복선 문장은 의미심장한 감속·저음·강조 없이 평문으로 읽는다.

## 5. 회차별 수정 입력

### E001 — PASS

- 현행 v2는 UI와 물리 표지의 구분이 이전보다 안정적이다.
- `07호`는 모든 위치에서 `공칠호`로 읽는다.
- 리안의 과거 인식은 설명자 톤이 아니라 현재 상황을 재는 내면 판단으로 유지한다.

### E002 — PATCH

- 하렌에게 붙는 미래 역할/별명 관련 문장은 **평문**으로 읽는다.
- 해당 문장 앞뒤에 의미심장한 정지, 저음, 강조를 추가하지 않는다.
- 하렌은 리안보다 감정 노출이 빠르고, 책임·명단·도착 후 문제를 더 직접적으로 묻는 화자로 구별한다.

### E003 — PASS

- 네라는 물리 고장·시험 조건·손의 문제를 먼저 말하는 화자 톤을 유지한다.
- 수치와 기체 상태를 빠르게 읽더라도 단위를 흘리지 않는다.

### E004 — PATCH

- 오르페우스와 ‘빈칸’의 기억은 독자에게 정답이 있다는 신호를 주지 않는 평문 톤으로 처리한다.
- 회상 진입은 속도만 조금 낮추고 미스터리 효과처럼 과장하지 않는다.

### E005 — PASS

- v2에서 UI가 크게 줄어 협상과 역할 분담이 중심으로 복원됐다.
- 리안/세린/하렌/네라가 같은 냉정한 화자로 수렴하지 않게 현재 voice lock을 유지한다.

### E006 — PATCH

- 조기 복선 문장은 평문으로 읽는다.
- 짧은 단문이 연속되는 구간은 각각 때리지 말고 원인→반응→결과의 한 호흡으로 묶어 읽는다.
- 헤더의 구명은 역사적 v1 메타데이터로 별도 취급하며, v2 이관 시 현행명으로 정리한다.

### E007 — REWORK

- 권한 범주, 판정 결과, 서비스 메뉴 등 대괄호 UI가 여러 차례 장면을 끊는다.
- 후속 v2에서는 **실제로 인물이 화면에서 읽어야 하는 정보만 UI로 남기고**, 나머지는 행동/서술/대사로 흡수하는 것이 필요하다.
- 조기 복선이 포함된 UI도 기계음 자체를 불길하게 연기하지 않는다.

### E008 — REWORK

- 서비스 정렬→결과→계정/상태 출력이 연속돼 낭독 모드가 사람↔기계 사이를 과도하게 왕복한다.
- 정보의 의미가 행동으로 확인되는 항목은 중복 출력하지 않는 방향으로 v2 입력을 만든다.

- 실제 본문 UI `[안전위반 책임자 — 리안 카르도]`에 구명이 노출된다.
- v1 역사 보존 자체는 정본 오류가 아니지만, **현재 낭독본으로 사용하면 현행 주인공명 `리안 칼데르`와 충돌**한다.
- 따라서 E009 v1은 현행 낭독용 배포본으로 PASS 처리할 수 없다.
- UI 클러스터도 함께 축소해야 한다.

### E010 — REWORK

- 등록부/사망/서비스 상태가 연속되며 인물 반응보다 기록 낭독의 비중이 커진다.
- 후속 v2에서 한 장면의 핵심 판정만 기계음으로 남기고, 나머지는 공식 기록 톤 또는 인물 반응으로 흡수한다.

### E011 — PATCH

- `피의 제독`은 미래를 아는 서술자의 예고처럼 읽지 않는다.
- 붉은 글자/표시라는 시각 정보가 있어도 음성은 중립적으로 유지한다.
- 하렌의 분노는 리안식 냉정함이 아니라 책임과 사람 쪽으로 더 빨리 튀어나오게 구별한다.

### E012 — PATCH

- 조준선·사격 기록은 짧고 명료한 장비/기록 톤으로 읽는다.
- 실제 인물 판단과 기록 출력 사이에 짧은 호흡을 둬 화자 혼선을 막는다.

### E013 — REWORK

- 파일명은 v1인데 내부 `Revision: v2` 표기가 있어 제작 단계 식별이 혼동된다.
- `NERA VICK — CLOSED`는 화면 표기를 그대로 영문 낭독할지, 현행 독자-facing 발음으로 읽을지 제작 규칙이 모호하다. 현행 캐릭터명 음성은 **네라 비크**로 고정한다.
- 제목과 종료 표식을 ‘사망 확정’처럼 연기하면 복선을 선행할 수 있으므로 중립적으로 읽는다.

### E014 — PATCH

- 인증품/재고/물품 기록은 전부 같은 기계음으로 만들지 말고, 물리 문서·기관 기록·시스템 출력을 분리한다.
- 네라의 반응은 기술적 시험 조건과 물리 결함 중심으로 유지한다.

### E015 — PATCH

- 대화 자체의 화자 구별은 E006~E014보다 안정적이다.
- 짧은 기록/UI 구간만 공식 기록 또는 기계음으로 명확히 분리하면 된다.

### E016 — PATCH

- 제목부터 `07호`는 **공칠호**.
- 기동·전투 구간에서 속도를 올리되 수치, 방향, 기체 상태 문장을 잘게 절단하지 않는다.
- 네라와 리안이 둘 다 ‘정확한 기술자’처럼 들리지 않게 네라는 물리 조건, 리안은 비용/거리/선택으로 구별한다.

### E017 — PATCH

- 사고 보고·기록 문장은 공식 톤, 현장 대사는 인물 톤으로 분리한다.
- 기록의 문장 파편성을 일반 서술까지 끌고 오지 않는다.

### E018 — REWORK

- 문서/기록/UI가 긴 구간 동안 연속되어 인물 행동과 감정의 음성 공간을 압도한다.
- 조기 복선 회차이므로 기계음의 불길함을 추가하면 스포일러가 된다.
- 후속 v2에서는 핵심 증거 1개를 음성 중심에 두고 나머지 기록은 인물의 확인·반응으로 흡수하는 방향이 필요하다.

### E019 — PATCH

- 장부/계정 문장은 회계 기록처럼 건조하게 읽는다.
- ‘이름이 없음’이나 누락 자체를 의미심장하게 늘이지 않는다.
- 세린은 출처/증언/정정의 언어로 리안과 구별한다.

### E020 — PATCH

- 핵심은 세 사람의 답을 같은 영웅적 선언 톤으로 합치지 않는 것이다.
- 리안은 비용·선택, 하렌은 사람·책임, 네라는 물리·기체 조건의 음성 차이를 유지한다.
- 여러 기록이 수렴하는 후반부는 장엄한 진실 공개처럼 과장하지 말고, ‘현재 확인되는 사실이 겹친다’는 공식·평문 톤을 유지한다.

## 6. 교차 결함

### N1. v1 UI 과다

E007~E010, E018에서 가장 크다. 시스템 UI가 장면당 반복되면 낭독자가 아무리 잘 읽어도 인물 장면이 ‘기계 보고서 사이의 대화’처럼 들린다.

**권장:** v2 개정 시 `화면에서 실제로 읽어야 독자가 이해하는 1개 핵심 출력`을 우선 남기고, 중복되는 상태값은 행동·반응·공식 기록 서술로 전환한다.

### N2. 복선 억양 스포일러

E002, E004, E006~E008, E011, E013, E018~E020에서 특히 주의한다.

**권장:** 키워드를 알고 있는 제작자가 ‘중요한 문장’처럼 읽지 않는다. 첫 독자가 아직 중요성을 모르는 수준의 평문 억양을 유지한다.

### N3. v1 구명

E006~E020의 v1 메타데이터에 구명이 남아 있는 것은 역사적 보존 범주다. 그러나 E009처럼 본문 UI에 노출되면 현행 낭독본으로는 직접 충돌한다.

**권장:** v1 파일을 조용히 고치지 말고, 각 회차가 v2로 이관될 때 현행명 잠금에 맞춰 수정한다.

### N4. 화자 평준화 위험

리안, 네라, 세린은 모두 정확성을 중시하기 때문에 낭독자가 모두 낮고 냉정하게 읽으면 구별이 사라진다.

- 리안: 비용/시간/거리/선택
- 네라: 물리 실패/시험 조건/손
- 세린: 출처/증언/정정/공식 기록
- 하렌: 사람/책임/도착 후 결과

## 8. 결론

E001~E005 v2는 낭독 기준에서 **3 PASS / 2 PATCH / 0 REWORK**로, 첫 배치의 문장·UI 개정 효과가 확인된다.

E006~E020 v1은 **0 PASS / 9 PATCH / 6 REWORK**다. 가장 큰 원인은 설정 결함이 아니라 v1 특유의 UI 반복, 기록문 연속, 복선 문장의 연기 위험이다.

따라서 현재 1~20화 전체를 하나의 오디오/낭독 원고로 곧바로 사용하는 것은 권장하지 않는다. E001~E005는 현행 하네스 적용 조건으로 사용 가능하고, E006~E020은 이 감사 결과를 각 v2 개정 Context Pack의 입력으로 승계하는 것이 맞다.
