## 1. Executive Ruling

《은하유산록》에는 ORIGIN, SUPERIOR, Mk-II, EX, Custom을 대체하는 고유 기체 계보 언어가 필요하다. 그러나 모든 장비 교환을 새 기체로 부풀리거나 매 단계마다 별명을 추가하면 독자 기억 부하와 변형 피로가 생긴다.

권장안은 **Lineage Mark / 계보 마크** 체계다.

> **FIRSTMARK → 기본형 → FACET → TEMPER → INTEGRAL → RESOLVE**
>
> 진짜 후계기는 새 ID와 새 고유명을 받고 INHERIT 관계로만 전대 기체와 연결한다.

이 체계는 강함의 단순 서열이 아니라 **기체가 자기 계보와 어떤 관계에 있는지** 표시한다. 기존 기체의 출력만 높였다는 이유로 상위 단계가 되지 않는다.

모든 명칭과 액시엄 예시는 PROPOSED — NONCANON이다.

## 2. Why Another Layer Is Needed

현재 수집 등록표 415행에는 기체·부품·상태·권리·세트가 섞여 있다. 따라서 업그레이드 형태를 모두 새 고유 기체로 합산하면 수집량이 허위로 팽창한다.

분리할 것은 세 가지다.

1. **Entity**: 같은 개체인가, 새 차체인가.
2. **Lineage state**: 임무 환장, 영구 개량, 대파 재구축, 통합형 중 무엇인가.
3. **Reader name**: 독자가 실제로 기억해야 할 이름인가.

[[reader-facing-terminology-phonetics-and-register-bible-v1]]의 3단 명명 규칙에 따라 한 기체는 일상명 하나, 필요한 정식 ID 하나, 사건으로 획득한 역사적 별칭 하나만 가진다.

## 3. Four Directions Compared

| Direction | Ladder | Strength | Risk | Verdict |
|---|---|---|---|---|
| A. Proofline | PREMISE / AXIS / VECTOR / AMEND / SYNTHESIS / CODA / SCION | 논리적 서사가 선명함 | AXIS·VECTOR가 액시엄과 발음·상품 충돌을 일으킬 수 있음 | 보조 어휘 |
| B. Service Rebuild | TRACE / VECTOR / TEMPER / RECAST / SYNTHESIS / LASTLIGHT / NEXTLINE | 공학 상태가 구체적임 | 단계가 많고 TRACE·VECTOR 외부 충돌 위험 | 코드 설계 참고 |
| **C. Lineage Mark** | FIRSTMARK / FACET / TEMPER / INTEGRAL / RESOLVE / INHERIT | 발음, 의미, 수집성, 독자 부하의 균형 | FIRSTMARK 길이와 INTEGRAL 발음 테스트 필요 | **권장** |
| D. Record Line | TRACE / LINE / ASPECT / RECAST / INTEGRAL / LASTLINE / CONTINUANT | 기록·계보 주제가 강함 | LINE·TRACE가 범용적이고 CONTINUANT가 어렵게 들림 | 일부 채택 |

선정 기준:

- 한국어로 한 번 듣고 다시 말할 수 있는가;
- 장비 교체와 새 기체를 구분하는가;
- 오래된 원형이 자동으로 최강이라는 오해를 피하는가;
- 후계기를 II나 Mk-II로 처리하지 않는가;
- 작품의 기록·수리·계승 주제와 맞는가;
- 다른 메카 프랜차이즈의 대표 문법을 직접 재사용하지 않는가.

## 4. Selected Lineage Marks

| Mark | Korean reading | Function | What changes | Reader exposure |
|---|---|---|---|---|
| FIRSTMARK | 퍼스트마크 | 기록과 실물로 확인 가능한 최초 계보형 | 별도 선행 차체 또는 최초 검증 구조 | 계보 공개 때만 |
| no suffix | 기본 고유명 | 안정된 기준형 | 기준 차체와 인증 사양 | 항상 |
| FACET | 패싯 | 가역적 임무 파생형 | 외장 장비, 소프트웨어 프로필, 탄약·센서·공구 구성 | 대표 1개만 전면 |
| TEMPER | 템퍼 | 실전·정비 기록을 영구 반영한 개량형 | 골격·동력·냉각·제어 중 2개 이상과 재인증 | 주요 성장 전환 |
| INTEGRAL | 인테그럴 | 검증된 파생 기술을 기본 구조에 재통합한 상위형 | 구조 전체의 부하·열·제어 재설계 | 대표 상위형 |
| RESOLVE | 리졸브 | 특정 결전을 위해 선택지를 포기한 비영구 결전 사양 | 임무 외 성능·수명·복구성 일부 희생 | 한 번의 결전 |
| INHERIT | 인헤릿 | 새 기체가 설계 책임과 원리를 계승하는 관계 | 새 차체 ID와 새 고유명 필수 | 후계 공개 때 |

### 4.1 Meaning controls

- FIRSTMARK는 완벽한 진짜 원본이나 최강형을 뜻하지 않는다. 현재 증거로 확인 가능한 최초 계보형이다.
- FACET은 장착물을 떼면 기준형으로 돌아갈 수 있다. 새 고유 기체 수로 세지 않는다.
- TEMPER는 수리나 도색이 아니다. 영구 구조 변경과 재인증이 있어야 한다.
- INTEGRAL은 장비를 많이 단 형태가 아니다. 이전 파생 기능이 기본 골격·열·제어 구조에 흡수되어야 한다.
- RESOLVE는 FINAL이나 무조건 최강을 뜻하지 않는다. 특정 임무를 위해 다른 선택지를 버린 구성이다.
- INHERIT는 변형명이나 소유권이 아니다. 후계기는 독립된 이름·차체·비용·손실 경로를 가진다.

## 5. Formal Designation Grammar

    [PROGRAM]-[CHASSIS]/[LINEAGE MARK][GENERATION]-[MISSION]

Proposed display examples:

    LFX-X0/FM      [FIRSTMARK proper name]
    LFX-01         AXIOM
    LFX-01/F-[M]   AXIOM FACET-[MISSION]
    LFX-01/T1      AXIOM TEMPER
    LFX-01/I1      AXIOM INTEGRAL
    LFX-01/R-[X]   AXIOM RESOLVE

    LFX-02         [NEW PROPER NAME]
    INHERIT: LFX-01 AXIOM

The bracketed mission code, successor name and exact numbering are intentionally open. They are not approved canon.

### 5.1 Upgrade promotion gate

| Change | New public form? | Index treatment |
|---|---|---|
| weapon, shield or color swap | no | loadout/state row |
| reversible mission package | normally no; FACET only when story-relevant | same entity + configuration |
| software patch or sensor calibration | no | update record |
| permanent change to at least two major systems | TEMPER candidate | same entity + structural state |
| integrated redesign of former packages and load paths | INTEGRAL candidate | same entity unless new chassis |
| one-operation high-risk fit that sacrifices alternatives | RESOLVE candidate | same entity + temporary state |
| new chassis, independent maintenance and loss path | yes, new proper name | new entity + INHERIT relationship |

Major systems are the load-bearing skeleton, power, propulsion, heat rejection, control architecture, armor, cockpit interface and weapon support/storage.

## 6. AXIOM Working Ladder

This is an application example, not an approved story arc.

| Stage | Display name | Collectible promise | Required visible difference |
|---|---|---|---|
| verified ancestor | [UNKNOWN] FIRSTMARK | find the machine's real technical ancestry | different chassis logic, not old paint |
| baseline | LFX-01 AXIOM | establish the iconic face, sword and body | stable family identity |
| mission branch | AXIOM FACET-[MISSION] | choose a capability and exclusion | package silhouette and stowage change |
| structural update | AXIOM TEMPER | war damage and field lessons become permanent | revised joints, cooling and load paths |
| integrated form | AXIOM INTEGRAL | separate strengths work as one machine | new mass hierarchy, not more spikes |
| decisive fit | AXIOM RESOLVE | one operation forces an irreversible choice | visible sacrificed capability and finite margin |
| successor | LFX-02 [NEW NAME] | the idea survives without copying the body | no more than two inherited visual motifs |

Reader-facing priority:

1. AXIOM;
2. AXIOM TEMPER;
3. AXIOM INTEGRAL;
4. AXIOM RESOLVE.

FIRSTMARK and FACET normally remain setting-book or limited-arc labels. Not every form should receive equal front-stage promotion.

## 7. 07 Boundary

The existing 07 lineage already has its own canon-controlled path: assigned scrap, diagnosis and tool recovery, asymmetry doctrine, external mission configuration, integrated victory, public-module replacement, post-damage rebuilding and final rescue/training service.

Do not rename these states 07 TEMPER, 07 INTEGRAL or 07 RESOLVE without author approval. The Lineage Mark system may classify them author-side, but it cannot replace the locked everyday name or final transformation path in [[first-frame-bible-v1]] and the project checkpoint records.

## 8. Collection Count Effect

Lineage Marks do not automatically add new unique collectibles.

| Layer | Recommended noncanon count for one flagship lineage |
|---|---:|
| baseline entity | 1 |
| front-stage forms | 3–5 |
| background FACET configurations | maximum 3 |
| historical FIRSTMARK | 0–1 |
| true successor entity | 0–1 |

A flagship with six states is still usually one entity plus state records. Only a true successor with a new chassis and independent operation/loss path becomes another entity.

## 9. Collision and Hard-Reject List

Do not use as the project-wide progression vocabulary:

- ORIGIN, ORIGINAL, SUPERIOR, SUPER, ULTIMATE, PERFECT;
- Mk-II, II, EX, Plus, Custom, Kai, Full Armor, Final Battle Ver.;
- PRIME, GENESIS, OMEGA, APEX, ZENITH, AWAKENED;
- CONCORD, because the repository already uses it for gates and fleets;
- ROOT, because the repository uses it for authority and AI identity;
- LEGACY, ARCHIVE, CONTINUITY, because they name work-level concepts and institutions;
- TESTAMENT, because an existing Gundam bears that name;
- THEOREM and COROLLARY as an AXIOM pair, because that exact logic-word family already appears in other robot properties;
- labels that imply a color swap, weapon swap or model-kit release is a new in-world chassis.

External comparison is diagnostic only. It does not authorize copying names or structures.
