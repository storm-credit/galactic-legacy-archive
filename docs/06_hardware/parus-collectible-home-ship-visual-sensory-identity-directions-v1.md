## 1. Locked Story/Engineering Facts Used

- NR-72 계전호위선, early production block.
- 31년 된 계류/노후 선체.
- 길이 134m, 최대폭 31m(radiator folded).
- 설계 crew 88, GA2 초반 실제 운용인원 부족.
- frame cradle 2개 설계 / 개막 가동은 1개, Bay 2는 냉각/발진 설비가 빠져 생활·화물·작업공간으로 사용.
- reactor 2기지만 공통 냉각 trunk 때문에 redundancy가 완전하지 않음.
- primary folding radiator wing 2개, 하나는 microfracture와 patched channel 문제가 있음.
- close docking/rescue/relay/tender 성격이 강하고 고가속 추격전은 약함.
- A~I 존의 bridge/CIC, crew drum, medical, workshop, Bay 2, cargo module, engineering, engine truss가 분명함.
- 선체 소유, lien, lease, insurance, crew wage/salvage, weapon/service permission이 분리됨.
- `Parus`는 왕실/포식자 명칭이 아니라 사람 사는 서비스 공간 근처에서 겨울을 나는 작은 새에서 온 승조원 이름.

## 2. Four Exterior Directions

### A — `Relay Bird`

Core silhouette:
- 전방 docking/sensor head가 짧고 분명함.
- 중앙 hull은 전투함처럼 두껍기보다 service spine / module volume이 읽힘.
- 후방 engine/truss가 함체의 `꼬리` 역할을 하지만 실제 기능 구조에서만 파생.
- folding radiators는 넓게 펴질 때 생명체 날개보다 산업용 열교환판으로 보임.

Reader effect:
- 작은 배가 큰 구조물에 붙어 살아가는 느낌.

Strength:
- 이름 Parus의 의미와 구조/계전호위 임무가 연결.

Risk:
- 실제 새 모양으로 의인화하면 실패.

### B — `Moving Workshop`

Core silhouette:
- workshop/frame bay/service access가 선체 중앙에서 읽힘.
- 외부 utility hardpoint와 tug/service geometry가 강함.
- patch/retrofit가 구조적으로 보이되 greeble 과다 금지.

Reader effect:
- 전함이라기보다 `공방을 들고 다니는 배`.

Strength:
- Nera/07/crew 생활과 직접 연결.

Risk:
- 너무 산업선처럼 보여 escort identity가 사라질 수 있음.

### C — `Half-Missing Home`

Core silhouette:
- Bay 1과 Bay 2가 동일한 완성 대칭이 아님.
- 두 번째 bay의 missing cooling/launch function이 `비어 있는 공간을 사람들이 생활공간으로 바꿔 쓴다`는 상태로 읽힘.

Reader effect:
- 미완성/부족이 곧 집의 성격.

Strength:
- progression fantasy를 출력이 아니라 `빈 공간을 어떤 기능에 쓸지`로 만든다.

Risk:
- 외부에서 과도하게 큰 빈 구멍으로 표현하면 구조상 부자연스러움.

### D — `Scarred Service Hull`

Core silhouette/material:
- 한 radiator root/wing의 patched thermal history가 반복 recognition anchor.
- 구식 replacement hardware의 비대칭이 미세하게 남음.
- 모든 외피를 새로 도색하지 않고 여러 시대의 service panel이 정돈된 형태로 공존.

Reader effect:
- 파루스의 나이를 설명하지 않아도 `살아남아 계속 고쳐 쓴 배`라는 느낌.

Strength:
- series-wide scar accumulation과 잘 맞음.

Risk:
- Frontier scrap aesthetic처럼 과도하게 낡고 더럽게 만들면 실패.

## 3. Recommended Hybrid

**A structural silhouette + C progression void + D scar language.**

B는 interior/close-up identity로 사용.

One-line recall:
> `두 장의 접히는 열판과 한쪽의 오래된 수리흔적을 달고, 빈 격납고를 사람 사는 방으로 바꿔 쓰는 작은 계전선.`

이 문장은 디자인 방향이며 새 정본 묘사로 자동 승격하지 않는다.

## 4. Exterior Recognition Anchors

### 4.1 Forward identity

- 넓은 전함형 함교창보다 docking/rescue sensor head의 기능이 우선.
- 접근장면에서 상대 선체/노드와의 거리감이 중요.

### 4.2 Mid-body identity

- module bay / frame service / habitation이 한 덩어리로 보이되, 무엇이 cargo이고 무엇이 crew space인지 외부 service marks로만 추정 가능.
- `완벽히 대칭인 군함`보다 mission history가 누적된 형태.

### 4.3 Thermal identity

- radiators deployed = 오래 버틸 수 있지만 더 잘 보이고 기동 제한.
- radiators folded = 좁은 docking/위기기동에 유리하지만 열 budget 감소.

독자는 `날개가 펼쳐졌다 = 파워업`이 아니라 `더 오래 버티기 위해 취약점을 노출했다`로 읽어야 한다.

### 4.4 Aft identity

- four primary engine clusters의 존재를 과장된 로켓노즐 판타지가 아니라 old escort/tender geometry로 번역.
- external utility/tow hardpoint가 전투함과 차별.

## 5. Interior Memory Anchors

### I1 — Crew Drum

Story function:
- 인공중력은 완전한 배경상수가 아니라 cruise/berth 상태에서만 돌아감.

Memory anchor proposal:
- 회전 시작/정지 때 생활물건 고정 방식과 사람 몸의 적응이 달라짐.
- `집이 돌아가기 시작했다`는 감각을 독자가 알아볼 수 있게.

### I2 — Bay 2 / Missing Room

가장 중요한 공간 수집욕.

Opening:
- 완전한 frame bay가 아니라 cargo + sleep + work 혼합.

Progression question:
> `두 번째 bay를 언제 고칠까?`가 아니라 `고치면 지금 여기 사는 사람과 화물을 어디로 밀어낼까?`

따라서 완성은 비용을 요구한다.

### I3 — Workshop / Bay 1

- 07과 Nera의 반복 공간.
- 공구와 부품이 늘어난다고 곧 `부자 배`가 되는 게 아니라 정비동선이 바뀌는 식으로 성장.

### I4 — Medical / Rescue

- 병원선이 아니므로 한계가 보임.
- medical overflow가 cargo/통로를 침범할 때 파루스의 좁음이 체감되어야 함.

### I5 — Bridge vs CIC

- 함장/항해 안전과 Rian mission command가 물리적으로 다른 자리에 있음.
- 이것이 권한분리를 대사 없이 보여주는 가장 좋은 공간 장치.

## 6. Sensory Grammar — Proposal

최종 원고 감각어는 Context Pack에서 조정한다.

### Sound

- crew drum/rotation state 변화;
- old pumps/cooling circulation;
- docking clamps;
- workshop machining;
- high-load 때 평상시와 다른 구조진동.

### Temperature

- heat budget가 나빠지면 `전투실만 뜨거워진다`가 아니라 habitation/workshop/medical priority에 차이가 생김.

### Smell

직접 고정명 대신 범주만:
- machine oil/cleaning solvent;
- galley/fermented stored food;
- medical disinfectant;
- crowded habitation.

### Touch

- handhold/strap/magnetic footwear가 생활 동작에 포함.

## 7. Crew Personalization Without Turning It Into A Theme Park

승조원 장식은 3층만 허용.

1. safety / shift / repair markings — 기능.
2. crew-made small identifiers — 생활.
3. one or two remembered communal objects — 관계.

금지:
- 벽 전체가 추억사진/낙서로 뒤덮인 우주해적 클리셰;
- 모든 승조원이 각자 화려한 방을 가짐;
- mission module마다 테마색.

## 8. Parus Progression States

### State P0 — `Laid-up inheritance`

- hull can move only under severe limits;
- one cradle barely useful;
- Bay 2 repurposed;
- one radiator history visible;
- rights fragmented.

### State P1 — `Working home`

- repair does not erase scars;
- crew routines stabilize;
- module choices become deliberate;
- Parus can accept missions but remains small/limited.

### State P2 — `Experienced ship`

- visible additions are selected for function, not prestige;
- crew/charter history becomes more important than armor/weapon escalation.

### State P3 — `Legacy vessel`

Final physical fate remains AUTHOR HOLD elsewhere.

Whatever option is chosen:
- strategic propulsion loss / permanent damage cannot be cosmetically erased;
- it must not become an ultimate flagship;
- its value must survive even if combat capability declines.

## 9. Collectible Desire Beats

The reader should want:

1. first departure — `이 배가 정말 뜰 수 있나?`
2. first safe sleep — `여기가 집이 될 수 있나?`
3. Bay 2 decision — `무엇을 포기해야 기능 하나를 되찾나?`
4. first serious damage — `고치면 무엇이 영구히 달라지나?`
5. first captured/new module — `무엇과 바꿔 실을까?`
6. later revisit — `예전 수리흔적이 아직 남았나?`
7. final return — `이 배는 누구의 배로 남나?`

## 10. Hard Veto

- bird wings / feather motif / beak-shaped nose;
- hero flagship proportions;
- main gun that solves fleet battle;
- cosmetic scar reset;
- every repair increases combat output;
- living space magically expands;
- crew and title treated as hull accessories;
- radiators used as decorative angel wings;
- Parus replaced emotionally by a bigger new flagship without narrative cost.
